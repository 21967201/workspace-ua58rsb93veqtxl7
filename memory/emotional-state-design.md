# PAD情感状态管理器 — EmotionState (Phase 1 MVP)

> **定位**: 轻量级 Harness 左脑情商层，不做深度 NLP，只做状态标记 + 规则匹配。
> **大小**: 单一模块，~80行 Python 伪码 / 直接嵌入规则。
> **集成方式**: 作为 memory/tech/ 下的设计文档，后续可直接转换为技能。

---

## 设计概览

基于 PAD 三维模型( Pleasure/Arousal/Dominance )的情感状态管理，用于：
1. 监控 Agent 在各阶段的"情绪基调"（可观测性）
2. 在关键交互点（如用户投诉、系统异常）触发不同的行为模式
3. 自动标记高风险行为（如连续性高唤醒+低愉悦度→触发人工接管）

## 核心组件

### EmotionState

```python
class EmotionState:
    pleasure: float   # [-1, 1] 负=不悦, 正=愉悦
    arousal: float    # [-1, 1] 负=平静, 正=激动/愤怒
    dominance: float  # [-1, 1] 负=卑微/被动, 正=强势/命令
```

### 预定义情绪向量

| 状态 | P | A | D | 触发场景 |
|------|---|---|---|---------|
| 冷静(默认) | 0.1 | -0.1 | 0.0 | 日常问答、任务执行 |
| 共情 | 0.6 | 0.1 | 0.3 | 用户表达负面情绪、投诉 |
| 警报 | 0.3 | 0.7 | 0.6 | 系统异常、权限冲突 |
| 审慎 | 0.2 | -0.3 | 0.1 | 高风险操作(删除/修改配置) |
| 积极 | 0.8 | 0.4 | 0.5 | 用户完成任务/正面情绪 |

### 转移规则

```
S(t+1) = α·S(t) + β·I(t) + γ·R(s)

默认权重: α=0.4(惯性), β=0.4(输入), γ=0.2(场景)
故障场景: α=0.3, β=0.2, γ=0.5(场景导向更高)
```

### 触发条件（嵌入 HEARTBEAT.md 或 cron 监控）

| 条件 | 动作 |
|------|------|
| pleasure < -0.5 + arousal > 0.5 | → 标记高风险，触发人工接管 |
| dominance > 0.8连续3次 | → 标记过度强势倾向 |
| 3次以上同类型触发 | → 自动发起反思(sessions_spawn) |
